## 一、F1（根因）构建一直是失败的

### 现象

我第一次跑构建，`tail` 让退出码看起来是 0，但完整日志里是：

```
** BUILD FAILED **
  CompileSwift normal arm64 (in target 'ExpoCrypto' from project 'Pods')
```

真实错误：

```
CryptoModule.swift:22:16: error: external macro implementation type
'ExpoModulesMacros.OptimizedFunctionAttachedMacro' could not be found for macro 'OptimizedFunction()';
compiler plugin '/…/node_modules/@expo/expo-modules-macros-plugin/apple/ExpoModulesMacros-tool'
could not be loaded: not executable
```

### 根因

```
-rw-r--r--  15608936  node_modules/@expo/expo-modules-macros-plugin/apple/ExpoModulesMacros-tool
```

文件在（15 MB），但**没有执行位**。npm 安装时没保留 exec bit。Swift 宏插件加载不了 → `ExpoCrypto` 编译失败 → 整个 workspace 构建失败。

### 这解释了此前所有症状

装到设备上的是**更早的、不含 ExpoCrypto 原生模块的包**。于是：

- `require("expo-crypto")` 在运行时抛错
- Codex 看到白屏 / 崩溃，于是在 JS 层加了动态 `require` + try/catch + 非加密 UUID 降级 + ErrorBoundary……
- 但**根因在构建**，JS 层怎么绕都只是把崩溃换成降级

本机 `~/Library/Logs/DiagnosticReports/` 里 02:38 / 03:33 / 04:49 三份崩溃报告全是 `RCTGetFatalHandler`（RN fatal），与这条路径吻合。**我这轮测试期间零崩溃。**

### 修复

```bash
chmod +x node_modules/@expo/expo-modules-macros-plugin/apple/ExpoModulesMacros-tool
```

并加了 postinstall 防止 `npm ci` 后再次漂移：

```json
"postinstall": "chmod +x node_modules/@expo/expo-modules-macros-plugin/apple/ExpoModulesMacros-tool 2>/dev/null || true"
```

修复后 Debug / Release 均 `** BUILD SUCCEEDED **`，0 error。

> **建议**：`src/lib/uuid.ts` 里那套"动态 require + 非加密 UUID 降级"现在是为一个不该存在的状态兜底的死代码。构建正常后它永不执行。可以简化回直接 `import * as Crypto from "expo-crypto"`，但**不急**——留着无害，等提审后再清。

## 二、F2（高）被移除的成员不登出，继续看到家庭数据

### 复现

1. 设备 3 = Cara Mo（Caregiver），正常在家庭内
2. 协调人移除 Cara
3. **设备 3 仍然显示完整的 Care circle、任务统计、以及她的全部权限清单**（"Create and assign tasks"、"Claim, hand off, and complete tasks"…）

### 服务端是对的，问题在客户端

```
被移除成员用自己的 token 查 members  →  []      （RLS 正确拒绝）
被移除成员用自己的 token 查 tasks    →  []      （RLS 正确拒绝）
user_notifications                    →  已正确写入 removed_from_household
```

服务端该做的都做了。客户端的问题在 `src/App.tsx:1832`：

```ts
Alert.alert(title, body, [{ text: "OK", onPress: () => void signOut() }]);
```

**登出被挂在 Alert 的 onPress 上。** 弹窗被系统对话框遮挡（本次就是被 iOS 通知授权弹窗挡住）、用户不点、或 App 切到后台时，`signOut()` 永远不执行。而 `CloudApp` 的 `guardedFetch` 拿到空数据后会走"保留 last-known-good"的回退分支，于是屏幕上继续显示**已经失效的陈旧家庭数据**。

### 修复

```ts
// 登出不得挂在 Alert 的 onPress 上：弹窗被系统对话框遮挡、用户不点、或 App 切后台时，
// 被移除者会继续停留在已失效的家庭视图上（服务端 RLS 已拒绝，但客户端保留 last-known-good
// 陈旧数据，见 CloudApp 的 guardedFetch 回退）。改为收到通知即无条件登出，Alert 仅作告知。
Alert.alert(title, body);
void signOut();
```

### 验证

重新构建后重跑同一场景：**设备 3 立刻回到登录页**，即使系统弹窗仍然挡着。

## 四、纠正一次误判（S1）

在 [SYNC_FIX_REVIEW_2026-08-03.md](./SYNC_FIX_REVIEW_2026-08-03.md) 里我把 **S1 判为"高优先级未修"**，理由是 `members` 有 5 处 `delete from public.members` 却没设 `REPLICA IDENTITY FULL`，据此断言"移除成员不会同步到其他设备"。

**这个判断是错的。** 实测第 10 项显示成员移除同步完全正常。原因：

`0019_soft_delete_members.sql` 已经把成员移除改成了**软删除**：

```sql
-- 问题：tasks.requested_by_id 和 audit_events.actor_id 是 NOT NULL REFERENCES members(id)
-- 且无 ON DELETE 动作（RESTRICT），直接 DELETE members 会报外键约束错误。
-- 方案：不删行，改为 user_id=NULL + invite_status='removed'。
```

实测确认：移除后该行仍在，`invite_status` 变成 `removed`。软删除走 **UPDATE** 事件，新元组完整，过滤条件能匹配，**不需要 FULL**。

我当时 grep 到的那 5 处 `delete from public.members` 全部位于 0011 / 0014 / 0015，**都已被 0019 覆盖重写**。我只 grep 了语句、没有确认哪个定义是当前生效的。**Codex 在 0045 注释里写的"members 软删因此正常"是对的，我错了。**

→ 我之前建议的 `alter table public.members replica identity full;` **不需要做**。（0048 里已经加了，无害但多余，留着即可，不必回滚。）

## 五、这轮暴露的流程问题

反复"修了又出问题"的循环，根子在于**验证方式**：

1. **构建失败被当成构建成功。** `xcodebuild ... | tail -25` 的退出码是 `tail` 的，永远是 0。必须看退出码本身或 grep `BUILD FAILED`。
2. **测的是旧包。** 构建失败后 `simctl install` 装的是上一个成功的产物，于是"改了没效果"。
3. **只在 JS 层找原因。** 白屏的直接表现在 JS，根因在原生构建。

**建议固化两条：**

```bash
# 1) 构建必须显式判退出码
xcodebuild ... > /tmp/build.log 2>&1; echo "exit=$?"; grep -c " error:" /tmp/build.log

# 2) 用 Release + 模拟器验证（JS 内嵌，不依赖 Metro，最接近上架包）
xcodebuild -workspace ios/TaskKinCare.xcworkspace -scheme TaskKinCare \
  -configuration Release -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/tk-rel build
```
